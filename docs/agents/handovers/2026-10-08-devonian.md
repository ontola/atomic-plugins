is open against `develop`. Branch: `codex/share-atomic-drive-skill`; head:

The PR contains `docs/skills/atomic-drive/` (instructions, setup reference,
Node helper, 21 tests and macOS Keychain C source), plus the book chapter
`docs/src/atomicserver/atomic-drive-skill.md` and its `SUMMARY.md` entry.
The existing personal installed skill was not changed.

The interface is assistant → local command tool → Node helper → signed Atomic
HTTP requests. The personal installation uses localhost:11870. Each colleague
configures their own server URL, agent and grants. This is not an MCP connection
or a persistent replication service.

Configuration supports `bootstrap.json`, `ATOMIC_SERVER_URL` (including host
and port), loopback HTTP or remote HTTPS, and either a trusted credential
command or an injected credential environment variable. Credentials are not
printed or placed in command arguments. The helper checks SDK compatibility
and agent identity. Environment-mode registry execution is refused before
fetching or caching scripts.

**Compatibility limit:** the helper requires unreleased compact-resource SDK
APIs and document adapters from the MCP work. Setup pins tested source revision
`0f9b5f4298e41a2da7360c847f455b724b7518ed`. The docs PR does not add these APIs
to `develop`; it does not establish compatibility with the published npm SDK.
Building document adapters does not mean an MCP process handles the requests.
