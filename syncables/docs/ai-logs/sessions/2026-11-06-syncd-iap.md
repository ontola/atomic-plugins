## Substantive human prompts

The maintainer described a vision across Unhosted, Solid, Atomic and ELFA,
with a virtual space and a laptop as a replica. They proposed focusing on
SyncD as the trailblazer: IAP is an Ontola service holding API credentials,
authorization grants and public webhook endpoints; durable imported data lives
in the client. They wanted one SyncD control panel to manage those remote
authorization sessions without switching applications. They explicitly chose
change notifications only for webhook retention, accepted a reusable IAP
management page, asked about CORS, and then asked: “can you build this
combination of SyncD and IAP?”

## Substantive assistant outputs and implementation

Inspected current main and reused its existing SyncD browser/status UI.
Added explicit connections:manage, sessions:manage and notifications:consume
permissions to IAP's device flow and described them on owner approval. Default
read grants and refresh cannot acquire management authority. Connection
management is restricted to selected connections; session management is
explicitly account-wide for the authenticated owner. Neither implies provider
reads/writes, runtimes, owner transfer or creating new provider connections.

Added an IAP management page/module with exact-origin/window message bridging.
SyncD's loopback backend executes only fixed grant operations. Its private
localhost token, JSON body and Origin checks protect mutations. Tokens and
owner keys never go to the iframe. ui --manage creates a fresh foreground
management session without changing the daemon's Keychain credentials.

Added notification-only receiver mode, bound to its database to prevent
accidental exposure of existing retained provider bodies. Bodies are verified
and routed transiently, then replaced with a fixed change hint before storage.
Device consumption is restricted to selected connections and receivers using
that mode. SyncD uses the existing InboxConsumer protocol and local PostgreSQL
subscription/work state: work is durable before acknowledgement; gaps cause
full bootstrap reads even when an incremental token was previously saved.

The combined panel was exercised in headless Chromium at desktop/mobile sizes
against a real local IAP process and PostgreSQL, with an invented provider
connection and real signed owner approval/device grants. A revoke-app action
traversed the iframe, SyncD backend and real IAP API successfully. Source-level scopes and receipt storage were separately checked
against real PostgreSQL. New provider connection onboarding continues through
the existing owner-hub/provider consent flow. Browser forms for collection
notification configuration are not implemented. Deployment still needs a
reviewed proxy release, SaaS wrapper bump, client/owner hub configuration,
provider hook configuration and the maintainer's local test.
